# タイムライン編集の引き継ぎ — 2026-11-20

Gemini 4 Neon への引き継ぎ。作業の基点は `main` の `114c0e6a`。この変更を含むコミットは `git log -- qa/TIMELINE_AUTHORING_HANDOFF_2026-11-20.md` で確認できる。製品バージョンは `1.2.0-rc.2`。

## ユーザーからの報告

- macOS で曲を「ソース」に落とすと、アプリがファイル再生画面に切り替わることがあった。Scene の配置、伸縮、再生にもつまずいたとの報告があった。
- 添付画面の Bank 1 とタイムラインは空だった。目盛りは編集範囲を示し、再生できる尺はまだゼロ。キュー音声の異常表示はモニター音声の状態を示す。
- 旧版で音声レーンがない場合は「編集 → タイムライン」で既存レーンの左端を右クリックし、「レイヤーを追加」で種別「音声」を選ぶ。♫ の `＋` から PCM WAV を選べる。

## 変更後の操作

| 操作 | 結果 |
| --- | --- |
| ソースの「音声クリップを追加」、または Finder／エクスプローラーからソースや ♫ の見出しへドロップ | 再生ヘッド位置に配置。ロック解除済みの最初の音声レーンを使い、音声レーンがゼロなら作成する。 |
| ファイルを音声レーンの波形領域にドロップ | 落としたレーンと時刻に配置。スナップ設定を適用する。音声ファイルは一つずつ。 |
| ソースの Scene を ⚡ のレーンにドロップ | 落としたレーンに配置。クリックで置く場合は、候補が複数なら先にレーンを選ぶ。 |
| 再生ボタン横の「速度」「繰り返し」を選び、Scene ブロックの上端をドラッグ | 速度は長さに合わせて再生レートを変更。繰り返しは速度を保ち、反復境界を表示する。秒ベースの繰り返しは一周期単位。拍ベースは途中までの最終反復も表示する。 |
| タイムライン末尾で再生を押す | ルートには先頭へ戻る案内を出す。子タイムラインは既存の再開処理を使う。 |

再生行の高さを 48 px から 46 px へ変更し、44 px のボタン高さを維持した。画面幅が 1180 px 以下ではクリック、ガイド、再生範囲のループ操作がタイムラインツールに入る。レーンが一つのセクションは実際の名前を種別アイコン右に表示する。複数レーンのセクションは見出しに種別を表示し、個別名を番号の隣に表示する。展開部には件数を残す。レーン名の隣接配置には Gemini 4 Neon Low の提案を取り込み、複数レーンの表示を追加した。

Daslight 5 公式フォーラムの説明では、伸縮でシーンの速度を変える設定と、伸縮を切って繰り返す操作がある。[速度の説明](https://forum.daslight.com/viewtopic.php?t=9239) [繰り返しの説明](https://forum.daslight.com/viewtopic.php?t=9345)

## 実装の入口

- `app/src/fileDropRouting.ts` と `app/src/nativeFileDrop.ts` が OS 由来のドロップを振り分ける。Windows メイン画面は WebView2 の既存ファイル解決、macOS メイン画面は Tauri のドロップ通知を使う。固定 Wry のコールバックはファイルがあるドラッグを処理し、アプリ内の HTML ドラッグを WKWebView に渡す。
- `app/src/App.tsx` の `importTimelineAudioClip` がファイル選択とドロップを共通化する。音声解析前に配置時刻とプロジェクトを捕捉し、レーン作成とクリップ追加の IPC に期待するプロジェクト情報を渡す。
- `app/src/timelineBlockGestures.ts` が伸縮を計算し、`timelineSceneBlocks.ts` が確定する。固定時間のレートは既存の保存フィールド `TimelineCueEventSummary.rate` を使う。タイミング更新の省略可能な `rate` は、未指定なら既存値を保持し、拍に同期したブロックのレートはエンジンが決める。リンク済みアイテムの端ドラッグは既存のグループトリムを使う。
- `app/src/components/TimelineOperatorBar.tsx` と `TimelineOverview.tsx` に再生行、レーン名、ハンドル、反復境界がある。

## 確認済みと残り

- 音声ドロップのブラウザ検証は日本語／英語の 4 ケースで通過。ソースや ♫、SVG 音声レーンへの振り分け、形式の拒否、内部ドラッグ、古いプロジェクトへの遅延応答の拒否を検証した。
- Scene のクリックとドラッグ、映像・音声の関連素材の配置は `node app/scripts/check-viewport-containment.mjs --timeline-source-placement-only` で通過。既存のバックグラウンド読み取り 2 件を明示的に模擬し、配置のトランザクション断言を維持した。
- 再生行とレーン名はブラウザの 1920×1080、1366×768、1280×720、960×640、860×520 で確認した。単一レーンの「Audio 1」、反復境界のプレビュー、未選択ブロックの端ドラッグも独立したブラウザ用データで確認した。レーン展開とミュートのブラウザ検証も 5 ケースで通過した。
- シーンブロック、外部ドラッグ、ソース、トランスポート、詳細編集、Tauri IPC のフォーカス検証は通過。`check-timeline-performance-browser.mjs` は 1920×1080 のタイムラインを通過した後、1366×768 の映像ワークスペースで Media Library の見出しに到達できず停止した。
- 最終差分の Windows `tauri build --no-bundle` は専用プロファイルで通過した。固定 MSVC リンカーと固定 LGPL FFmpeg SDK を検証し、Cargo のリンク参照先も確認した。ビルド出力の警告は 0 件。固定 SDK での変更前の警告数は未計測。生成した実行ファイルから応答する `Syndocal` ウィンドウを一つ確認した。証跡は `windows-native-handoff-pinned-build.log` と `windows-native-handoff-pinned-startup.json`。
- Windows のファイル選択と Explorer 実ドロップ、Mac の Finder 実ドロップと Retina 座標、実案件での Scene 操作、音声の聴取、物理出力は未確認。固定 Wry には一部のファイル参照で起きる既知問題があり、最初は Finder 上の通常のローカル PCM WAV を使う。[Wry の修正履歴](https://github.com/tauri-apps/wry/pull/1844)

## Neon の最初の確認

1. `git status --short --branch` と `git log -5 --oneline` で現在の状態を確認する。確認時の作業ツリーにはライブスナップショット同期、タッチ編集、ステージ表示などの並行作業の差分があった。作業を始める前に差分の所有者と範囲を確認する。`target/qa/timeline-audio-drop-20261120/` に Windows ビルドログ、ブラウザキャプチャ、Neon のレイアウト提案がある。
2. Mac の空プロジェクトを使い、WAV をソースへ落として最初の音声レーンができることと、音声レーンの別時刻へのドロップで指定時刻に置けることを確認する。同じ画面で Scene のアプリ内ドロップも確認する。
3. 時間変化の見える Lighting Scene で速度を短縮・延長し、反復で再生レートが維持されることと、境界が見えることを確認する。単一と複数のレーン名、長い名前の省略、♫ の `＋`、ルートと子タイムラインの再生を確認する。
4. Windows で取り込み操作を確認する場合は [Windows のビルド手順](WINDOWS_NATIVE_BUILD.md) を使う。`FFMPEG_DIR` を変えても既存の Cargo 出力に以前の SDK へのリンク参照が残る場合があるため、SDK の検証に加えて `ffmpeg-sys-next` のリンク参照先を確認する。試験中は照明・映像出力を有効化しない。ネイティブでの結果とブラウザの結果をそれぞれ記録する。
